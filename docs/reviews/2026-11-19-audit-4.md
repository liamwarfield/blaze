## Blocking findings

### F1 (S1). `run` and `java` report IDENTICAL while stderr differs

Both compare stderr through an include filter (`run/compare:124-126`, `java/compare:126-127`).
Stored evidence, `~/.cache/blaze/run-compare/audit3-run-2`, full stderr with paths and times
replaced:

| Case (class today) | Oracle | Blaze |
| --- | --- | --- |
| `not-executable`, `two-targets` (IDENTICAL, declared) | `INFO: Elapsed time: <T>s` | `INFO: Elapsed time: <T>s, Critical Path: <T>s` |
| `build-fails` (IDENTICAL, declared) | no `Found` line at that point | `INFO: Found 1 target...` after `Analyzed` |
| `show-args`, `subcommands` (IDENTICAL, declared) | `INFO: 1 process: 1 internal.` | `INFO: 1 process: 6 action cache hit, 1 internal.` |
| every case | `Analyzed … (0 packages loaded, …)`, no server line | `(87 packages loaded, 468 targets configured)`, `Starting local Bazel server…` |

- The last two rows are the warm-server against cold-process asymmetry of round 3 (B1). The
  first two are not explained by it; I did not determine their cause.
- `java` (sub): in stored `java-5`, cquery and aquery stderr are not compared at all; the
  `Elapsed` line has `Critical Path` on one side only, `Found 31 targets` sits at another
  position. All 18 steps are IDENTICAL.
- Fix: compare the whole stderr and remove only named timer-driven lines, as `cmds` does. The
  cold-against-warm lines become a declared gap that cites B1, not a silent drop.

### F2 (S1). `repo-gaps` never compares stdout, and its selftest was changed to hide that

- `repo-gaps/compare:315-319` judges termination and filtered stderr lines only; stdout is
  stored and never read. For `al-mock-android#0` and `#1` the query stdout is the result.
- `repo-gaps/compare:327-331` (verified): the selftest appends each fake's stdout to the
  compared lines as `"ERROR: " + stdout`, with the comment "which this tool does not compare".
  On the real path the `different` scenario is IDENTICAL.
- No stored verdict is wrong because of it (sub: stdout equal in all 22 rows of `cand2`).

### F3 (S1 by reading, not observed). Reuse paths that judge unanchored or wrongly anchored captures

- **`config --skip-oracle`** (verified, committed file): the key is `oracle/oracle.key`, the
  data read is `results.json["oracle"]`. The key is written right after the oracle side;
  `results.json` only after the Blaze side. A run that dies in between leaves a new key beside
  the previous run's oracle results.
- **`mod`** (verified, `mod/compare:318-325`): the key is written before the output files.
- **Blaze captures have no key anywhere.** `cmds --side oracle` runs the oracle and then judges
  whatever is in `results/blaze/`, with the header line `blaze: -`, and can exit 0
  (`cmds/compare:720-740`). Same shape (sub): `query --no-run`, `mod --side oracle|none`.
- **`bytes/compare`**: a candidate recording without `provenance.json` is compared and can
  pass; a candidate recorded by the oracle is not refused (`bytes/compare:124-136`).
  `textproto bep-e2e` does not refuse an oracle-recorded candidate.
- Old key not removed before outputs are rewritten: `exec2`, `query`, `macros`, `tests`, `run`.
- `java` and `mod` pass `None` as tool sha256 while their help says the tool is in the key.

### F4 (S2). Two launches bypass the module

- `query/compare:362-377` (verified): the workerd branch runs `scripts/workerd/run` through
  `subprocess` with the caller's environment and no OOM detection. Its cache key
  (`:394`, `:400-406`) records an argv that never ran and a constant in place of a digest.
- `config/compare:267-269` (sub): `shutdown` is started with plain `subprocess`, outside any
  unit, result ignored.

### F5 (S2). The selftests cannot see a bypass

- In most tools `run_pair` calls `cc.require_oracle` and `cc.run` itself and builds the record
  by hand. The "wrong oracle refused" check tests a line that exists only in the selftest.
- No selftest covers `blaze_identity`, a reuse branch, a case table or a workspace preparation.
  `main` is entered only for the empty selection, which returns before the pin check.
- Proof that the answer to "can a selftest pass while the real path bypasses the module" is
  yes: `query` and `config` pass today with the bypasses of F4.
- Real-path coverage exists in: `textproto` (the real `check` on synthetic directories,
  including the crashed-aquery case), `bytes/compare` (`compare_dirs`), `interp-diff` (`run`
  and `judge_packages`), `proxy/classify`, and partly `cmds` and `run`.
- Fix: drive `main` with fake binaries under the pin override, including one reuse run and the
  oracle given as the binary under test.

### F6 (S1, claims). Numbers that must not go into the documents as given

See "Corrected numbers". "21 by declared exit code" is 13. "6 declared failures" is 7. "63
invocations identical" is 55 identical and 8 both-failed. "15 identical" for `run` and "18 of

## Other findings

**Module**

- **M1 (S2).** In scope mode a daemonized server stays in the scope of the command that
  started it. An OOM kill of that server during a later command is not in the later unit's
  counter and is recorded as the client's `exit N`. It cannot produce a pass.
- **M2 (S2).** Terminations of `shutdown`, `clean`, `info` and warm-up commands are dropped in
  `cmds`, `run`, `config`, `macros`, `tests`, `java`, `exec2`, `mod`, `query`, `bytes`.
- **M3 (S3).** `tree_digest` ignores file modes and empty directories, hashes a symlink's
  target text and skips every top-level `.git*` name. `repo_state` calls a tree with only
  untracked changes clean. No lock: two runs of one tool overwrite each other's work copies.
- **M4 (S4).** `cmds` help says the key holds the tool's sha256 and the digest of the work
  copy; it holds neither (`cmds/compare:82-85` against `:544-550`).

**cmds**

- **C1 (S3).** The corrected key is sound for what it names: pinned sha256, exact argv,
  environment, digest of the read-only corpus checkout, the cases run before. It is computed
  from the current constants, never read back. Leaving the tool sha out is right, since raw
  outputs are stored and normalised on load. Not in the key: what earlier runs left in
  `ur-cmds`, `ob-<project>` and the repository cache; a `--case` run starts with an empty
  sequence over that state.
- **C2 (S3).** `canonicalize-flags outside workspace` declares exit 37, Bazel's
  NullPointerException. Blaze prints a Rust panic, so the case is DIFFERENT for ever and the
  full list can never exit 0. It needs a declared gap for the stack trace or its own rule.
- **C3 (accepted).** Dropping `    currently loading: ` lines: this is the second line of the
  timer-driven `Loading:` message; the pattern is anchored at the line start. No other rule
  changed.
- **C4 (S3). Cases that do not measure what they name.** Exit 8 is Bazel's own code for a
  failed fetch (`FetchCommand.java:253`).
  - `fetch re2` (empty, warm, `--all`): the oracle fails on `Unknown host:
    netcologne.dl.sourceforge.net` while downloading libpfm. They measure a download failure of
    this machine at that minute, not fetch.
  - `fetch brotli --force --repo=@platforms`: `No repository visible as '@platforms'`. It
    measures the `@nosuch` error again, not `--force`.
  - Both are BOTH-FAILED and undeclared, which is the right class.

**run, textproto, bytes, proxy, interp-diff**

- **R1 (S3).** `textproto check` labels the aquery row "printer, reprint, round trip" while the
  printer comparison differs and is waived (`textproto/compare:176-181`, the owner's rule: two

- **R4 (S2).** `interp-diff` sorts DEBUG lines per package (`interp-diff:150`). Query stdout is
