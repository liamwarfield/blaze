## SkyQuery (first review)

Found faithful:

- **Which environment.** `!orderedResults && !universeScope.isEmpty() && packagePath != null`
  (`strictScope` true, `ALL_LABELS`), as `QueryEnvironmentFactory.canUseSkyQuery`; so an ordered
  output (`--order_output=deps|full`, or a formatter that does not stream) keeps the graph
  environment even with a universe, as Bazel. `--universe_scope` wins over
  `--infer_universe_scope`.
- **Universe.** Constant: the given patterns. Inferred: the target patterns of the *original*
  expression in first-seen order without duplicates (`collectTargetPatterns` into a
  `LinkedHashSet`), with the parser's offset; the key is `PrepareDepsOfPatterns`.
- **Rewrites.** Only with a constant universe of exactly one pattern that parses.
  `rdeps(<u>, x[, d])` becomes `allrdeps(x[, d])` for the same single target, or the same
  directory with the same rules-only flag; `kind(" rule$", allrdeps(...))` when the universe is
  wider (`:all-targets` or `:*` against `:all`); nothing when it is narrower. The filter mapper
  applies to the 3-argument form with depth 1 only. The composition runs the last mapper first,
  as `mapAll`.
- **Results that differ from the graphless environment, as in Java.** Forward deps are graph
  edges filtered by `getAllowedDeps` (transitions' labels, visibility labels unless
  `--nonodep_deps=false`, toolchain types unless `--noimplicit_deps`, aspect labels); reverse
  deps are filtered the same way only when a dependency filter is set; `rdeps` with an explicit
  universe uses the unfiltered transitive closure of the universe expression as a key predicate,
  filters the start set in the unbounded visitor and not in the bounded one
  (`RdepsBoundedVisitor.preprocessInitialVisit`); `rbuildfiles` and `allrdeps` exist only here;
  `somepath` picks the first element of the intersection in the Java hash order the set type
  models; `preloadOrThrow` does nothing.
- **Errors outside the universe.** A package not in the graph: `getTarget` throws
  `<pkg> does not exist in graph` with `Query.Code.CYCLE` (sic, Java) or
  "Package depends on a cycle"; pattern evaluation reports "BUILD file not found on package
  path" through the graph-backed provider; unsuccessful and missing keys give the warning
  `Targets were missing from graph: [...]` (labels printed as `Label.toString`) and one
  `handleError` per stored error; `checkEvaluationResult` raises "Building universe scope".
- **`rbuildfiles`.** Start keys (FILE_STATE and FILE under the root of the nearest ancestor
  package, the main repository mapping for `WORKSPACE`/`WORKSPACE.bazel`), the pruned node
  types, the `//external` package special case and the PACKAGE_LOOKUP/GLOB/GLOBS cut are Java's.
  It relies on Blaze's graph having Bazel's edges between FILE, BZL and PACKAGE nodes; not
  probed.
- **Computed-default class names.** `BaseRuleClasses$1..$4` are javac's numbers for the pinned
  source: the four anonymous classes at `BaseRuleClasses.java:69, 78, 87, 103` are the first
  four of the top-level class in textual order (the next, `:503`, is `$5`);
  `GenRuleBaseRule$1` (`:297`) and `ConfigFeatureFlag$1` (`:80`) are the only anonymous classes
  of their files. A native computed default without a name stops with `unported!`
  (`attribute_info_extractor.rs:79`), as does a native late-bound default: nothing is guessed.

### S2

- **SQ-1. Order inside the missing-targets warning.**
  `sky_query_environment.rs:632-646` collects `missing_targets` in insertion order; Java
  `SkyQueryEnvironment.java:1228` uses a `HashSet<SkyKey>` and prints it
  (`Targets were missing from graph: [a, b]`). With two or more keys missing in one batch of
  `deps(...)` the text can list them in another order. Masked: needs two labels of one batch
  whose packages are loaded and whose targets do not exist. Fix: the Java hash order of the
  labels (the engine already has `JavaConcurrentHashMap`/Java `hashCode` for labels).
- **SQ-2. Direct deps of a node that is done without value or exception.**
  `get_fwd_dep_labels` (`:471-476`) skips a key with neither value nor exception; Java
  `graph.getDirectDeps` returns the deps of every done node, which includes a node in a cycle.
  Masked: needs `deps()` through a target whose TRANSITIVE_TRAVERSAL node is on a cycle. Fix:
  test "done" on the node, not value-or-exception.
- **SQ-3. Evaluation is sequential** where Java uses a pool (declared in the file header). The
  result sets are the same; the stream order is fixed in Blaze and scheduling-dependent in
  Bazel, which only unordered outputs can show. Listed because no ruling in `docs/decisions.md`
  was cited for it.
