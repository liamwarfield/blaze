## Points the task asked to confirm

- **File-system values.** `FileStateValue`, `FileValue`, `DirectoryListingStateValue`,
  `DirectoryListingValue`, `GlobsValue`: field for field Java's `equals`. Java's
  `SymlinkFileValueWithStoredChain` accepts its subclass (`instanceof`); Rust variants never
  cross (prunes less).
- **Package values, `BzlLoadValue`, `ConfiguredTargetValue`, `AspectValue`**: default, never
  equal.
- **Registries by identity.** `ModuleFileKey` and `BazelModuleResolutionKey` add
  `Arc::ptr_eq` on each `InterimModule.registry` to `==` (`blaze_bzlmod/src/skyframe/keys.rs:73-96,
  154-171`); no other opted-in value holds an `InterimModule` or a `Registry`.
- **`PlatformValue`.** Equal only when both have a `PlatformInfo`, `PlatformInfo.equals` holds
  (the nine fields of `J:lib/analysis/platform/PlatformInfo.java:182`) and the parsed flags are
  equal. The other three Rust fields are projections of those two
  (`blaze_sky_analysis/src/platform/platform_function.rs:135-150`). An oracle-recorded value is
  never equal.
- **`ActionExecutionValue`, artifact values.** Confirmed: a value with any tree artifact or with
  rich artifact data is never equal; a file value that is, or wraps (`ResolvedSymlink`, `Proxy`),
  a remote file is never equal; `ArtifactValue::Tree` and `::Missing` are never equal
  (`blaze_sky_exec/src/keys.rs:29-39, 64-77, 100-107`). Source file values carry digest, contents
  proxy and size, as `J:lib/actions/FileArtifactValue.java:319-383`.
- **`PackageDeclarationsValue`.** The Rust `PackageDeclarations` carries the packageoid's error
  flag and failure detail, which Java's `Declarations` lacks and `==` ignores. Not a hole: the one
  reader, `EvalMacroFunction`, copies the declarations with the flag reset
  (`blaze_packages/src/package/package_piece.rs:612`, `package.rs:258-266`), so a pruned parent
  never reads the BUILD-file piece's flag through this value.
- **Completion and conflict-finding values** (`values_equal` = `true`): the four Rust value types
  are unit structs, like Java's singletons.
- **`Precomputed<T>`.** Every `T`'s `==` is Java's `equals` or stricter. `PathPackageLocator`
  compares path entries and output base only, as `J:lib/pkgcache/PathPackageLocator.java:301`.
- **Java equalities that ignore a field** are ported as they are, not widened further:
  `LocalRepositoryLookupValue.Successful` (name only, `J:lib/skyframe/LocalRepositoryLookupValue.java:174`),
  `TargetPatternPhaseValue` (no `nonExpandedLabels`, `J:lib/skyframe/TargetPatternPhaseValue.java:118`).

### S2

**S2-1. Hermetic keys whose Rust functions read the file system outside the graph.** Not
blocking for this package (no equality is involved); blocking for I3, the switch to a graph kept
across commands.

- `blaze_sky_exec/src/artifact_function.rs:436-449` (`create_source_value`): stats and digests
  the source file itself. Java requests `FileValue.key(path)`
  (`J:lib/skyframe/ArtifactFunction.java:279-282`). `ArtifactKey` declares `Hermetic` and opts
  into `values_equal`.
- `blaze_build_config/src/skyframe.rs:328-331` (platform mappings file): stat instead of
  `FileValue.key(rootedMappingPath)` (`J:lib/skyframe/config/PlatformMappingFunction.java:92`).
- The other sites of `i2-worklist.md` section C ("7 production bypasses in 4 files plus 1
  decision item": module files, includes and patches in `MODULE_FILE`, the lockfile,
  generated-input metadata from a stat). I verified only the two above at 5f68157.

Input that shows it, once the graph is kept: build, edit a source file, build again. The
`ARTIFACT` node has no dependency that the edit dirties, so it is never re-run and `values_equal`
is never asked; the action keeps its old input metadata and the build is stale. Why masked: one
evaluator per command (`blaze_sky_top/src/skyframe_executor.rs:1-10`). Fix expected: request
`FILE` as Java does, before I3. `i2-result.md` "Open" does not list these; it should, since I2
is the package that declared these keys hermetic.

### S3 (honestly marked)

- Deferred equality, all on the safe side (default or narrower): `MacroInstanceKey`,
  `NonFinalizerPackagePiecesKey`, `RepoFileKey`; tree artifacts, runfiles data and remote files
  in `ActionExecutionKey` / `ArtifactKey`; `RecursiveFilesystemTraversalValue.EMPTY`. Cost: every
  action with a tree output or a runfiles tree re-dirties its dependents.
- `TimestampGranularityMonitor` is skipped (`blaze_sky_loading/src/actions/file_state_value.rs:6-7`,
  `blaze_sky_exec/src/skyframe_action_executor.rs:2863`; Java
  `J:lib/actions/FileStateValue.java:161-163`). The contents proxy has millisecond resolution in
  both; without the monitor's wait, a same-size rewrite in place in the millisecond of the stat
  gives an equal `FileStateValue`. Must be ported with I3.
- `ErrorInfoValue.equals` is `unported!` (`value_with_metadata.rs`), reached only if an error
  value is compared; `unchanged_from_last_build` excludes it first, as Java's
  `NotComparableSkyValue` test does.

### S4

- `CoverageReportKey` (`blaze_analysis/src/coverage_report_value.rs:92`, hermetic, default
  equality, both correct) is missing from the `i2-result.md` table.
- `blaze_bzlmod_model/src/module.rs:207-208`: the comment says comparing registry URLs "is
  equivalent" to Java's identity; for pruning it is not, which is why `values_equal` adds the
  identity check. Reword.
