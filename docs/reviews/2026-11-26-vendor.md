## What was checked in depth and found equal to the Java

- Which repositories are vendored: `excludeFromVendoring` is `local || configure`, or ignored,
  or pinned; ignored and default-excluded repositories never take the vendored path; the
  override sources return `exclude_from_vendoring: true`.
- Up-to-date decision: the early `continue` when `external/<repo>` already links to the vendor
  directory, the marker choice (external marker, or `<cache dir>.recorded_inputs` when the
  external marker is absent), the string comparison of the two markers.
- Copy versus move: marker to `<marker>.tmp` first (copy when cached, move otherwise), tree copy
  from the resolved cache directory or `renameTo` with the `moveTreesBelow` fallback, then
  `bazel-external`, re-planting, marker rename, `deleteTree` and the back link. An interrupted
  run leaves the same states as Java (no marker under the vendor directory until step 5).
- Re-planting: workspace links through `external/_main`, relative links only classified,
  links leaving every repository left alone, same-repository and cross-repository targets
  computed with the same segment counts.
- Fetch path: pinned repository uses the vendored tree and deletes the marker; the two
  out-of-date warnings, the pinned-not-found (persistent) and `--nofetch` not-found (transient)
  errors have the Java texts and conditions.
- Registry files: `file:` URLs skipped, conflict detection on the lower-cased output path with
  the Java message, download only when a checksum is recorded, the
  `Failed to vendor registry URL ...` and `Failed to read vendored registry file ...` wrappers.
- Command: option validation texts and `OPTIONS_INVALID`, `Target patterns and --repo cannot
  both be specified`, the info lines of the three modes, `Vendoring some repos failed with
  errors: [...]`, `Error while vendoring repos: ...`, deletion of the vendored repositories'
  `REPOSITORY_DIRECTORY` nodes.
